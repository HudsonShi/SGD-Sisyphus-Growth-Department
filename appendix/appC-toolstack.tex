\chapter{工具、数据源与脚本清单}
\label{app:tools}

\begin{insight}[先说清楚一件事]
工具清单最容易变成「收藏夹吃灰」。这里给出的每一条都标注了\textbf{定位、成本、典型场景和坑点}，
请按需取用，不要试图全部学会。真正决定产出的不是工具数量，而是\textbf{你能不能把一个闭环跑通}：
数据能不能回流、指标能不能对账、实验能不能复现。
\end{insight}

\begin{toolbox}[如何真正用起来这套工具链]
按「一个人能跑通的最小闭环」排序，而不是按技术时髦度：
\begin{enumerate}
  \item \textbf{能用 SQL 拉出一张可信的漏斗表}（ClickHouse/DuckDB + 调度）；
  \item \textbf{能跑一次后端 A/B 实验并算对显著性}（GrowthBook 或自研）；
  \item \textbf{能训练一个小模型并上线做一次离线在线一致性校验}（PyTorch + 特征平台）；
  \item \textbf{能把广告平台数据与站内订单对账到差异小于 5\%}（CAPI/SS GTM + 自建归因）；
  \item \textbf{能把选品到履约的单位经济模型算准到单 SKU 级别}（ERP + 财务模型）。
\end{enumerate}
这五步走完，你对这条链路的理解会超过读十本书。
\end{toolbox}
