\chapter{Meta、TikTok 与其他付费渠道}
\label{ch:meta}

\begin{insight}[本章要解决的问题]
\begin{enumerate}
  \item 在 Meta 与 TikTok 上，为什么「素材就是定向」？当一个平台的排序模型已经能在几十亿用户里自己找人，
        人工堆叠的兴趣标签到底还剩多少价值？「定向收窄」与「广泛放量」的分界线在哪里？
  \item iOS ATT 之后信号损失究竟损失了什么？为什么平台后台的转化数之和经常大于你自己的订单数？
        在信号不全的情况下，投放模型还能靠什么工作？
  \item 素材工程为什么应当被当成一条\emph{生产线}而不是一次创意灵感？一周产 30 条素材的团队，
        与一个月产 3 条素材的团队，差距到底出现在流程的哪一环？
  \item 「素材疲劳」是可观测的还是要凭感觉？Frequency、$\CTR$、$\CPA$ 三个信号谁的置信度更高？
        在多长的观察窗口内、用多大的样本量，才能声称一条素材真的衰变了？
  \item TikTok 的 Spark Ads 为什么常用自然流量素材投放？达人的头部与腰尾部各承担什么职能？
        直播的 $\GMV$ 到底由哪几个乘性因子决定，哪一个因子最容易被低估？
  \item 冷启动的「学习期」与「50 次转化」门槛在实操中意味着什么？为什么一次改三个变量（受众、出价、素材）
        的扩量实验几乎必然失败？
  \item 当平台 A 报告 800 单、平台 B 报告 600 单、而你的后台只有 1000 单时，你该信谁？
        地理 holdout、PSA、品牌词暂停三种增量测试各适合回答什么问题，代价是什么？
\end{enumerate}
\end{insight}

\cref{ch:ad} 讲了计算广告的机制设计、\cref{ch:google} 讲了搜索与 YouTube 拍卖的工程细节，
但它们都默认了一件事：\emph{用户的需求已经用关键词或浏览意图表达出来了}。
Meta 与 TikTok 面对的是完全相反的场景——用户没有在找你的商品，他正在刷朋友的动态或看一条搞笑视频。
这意味着两件事：第一，投放系统必须从\emph{行为与内容}里推断他想买什么（这就是推荐系统而非检索系统，
参见 \cref{ch:recall}、\cref{ch:ranking}）；第二，打断他的那 3 秒里必须自带说服力。
于是行业里那句被说烂了的话有了精确的技术含义：\kw{在 Meta 与 TikTok 上，素材就是定向，创意即策略}。

这不是修辞。在检索式广告里，关键词承担了「把广告和需求连起来」的工作，素材负责锦上添花；
而在推荐流广告里，\emph{素材本身就是召回与排序模型的输入特征}：平台会把一条视频的钩子类型、卖点、
人物、节奏、前 3 秒画面都编码成向量，用它去匹配可能感兴趣的受众。
你换一条素材，等于换了一个投放目标的分布。本章的核心因此放在素材工程（\cref{sec:meta-creative}），
其他部分围绕它展开：账户与产品结构（\cref{sec:meta-structure}）、定向（\cref{sec:meta-targeting}）、
信号与追踪（\cref{sec:meta-signal}）、TikTok 的差异化打法（\cref{sec:tiktok}）、
其他次级渠道的定位（\cref{sec:meta-others}）、冷启动与放量（\cref{sec:meta-scaling}）、
最后是归因与对账（\cref{sec:meta-attribution}）。

技术性约定：Meta 与 TikTok 的广告产品名称、政策条款、费率与归因窗口默认值改动频繁，
本章凡是涉及产品政策、事件规则、窗口长度、竞价门槛的内容，一律\emph{以官方最新文档为准}
\cite{meta_advantage}；文中出现的所有数字都是「示范量级」或「行业经验值」，
用于说明数量级与判断方向，不作为可直接套用的基准线。

\section{账户结构与产品体系：从 Campaign 到 Ad}
\label{sec:meta-structure}

\subsection{三层结构：Campaign / Ad Set / Ad}

Meta 广告后台是严格的三层对象模型，理解每一层「承载什么变量」比记住界面按钮重要得多：

\begin{itemize}
  \item \textbf{Campaign（广告系列）}：承载\emph{目标}（Objective）与\emph{预算策略}（CBO）。
        目标决定系统优化什么事件、走哪条竞价与预估链路。这一层改错，等于整场实验作废。
  \item \textbf{Ad Set（广告组）}：承载\emph{受众}、\emph{版位}、\emph{排期}、\emph{出价与优化事件}。
        它是「把广告投给谁、愿意出多少钱」的声明。ABO（Ad Set Budget Optimization）模式下预算也在这一层。
  \item \textbf{Ad（广告）}：承载\emph{素材}（图片 / 视频 / 轮播 / 合集 / 即时体验）与\emph{文案与落地页}。
        它是唯一被用户看见的东西，也是本章投入最多笔墨的地方。
\end{itemize}

这个分层背后有一条重要的工程约束：\kw{预算与学习发生在哪一层，实验就必须在哪一层做}。
如果把预算放在 Campaign 层（CBO），系统会在 Ad Set 之间自动分配，你就无法用「同预算 A/B」
比较两个受众；反过来，如果你在 ABO 下想比较素材，就必须保证每个 Ad Set 的受众与出价完全一致，

\subsection{目标分类与「优化事件」的选择}

Meta 的目标（Objective）本质上是\emph{优化事件的声明}：你告诉系统「什么行为对我有价值」，
系统会用它的预估模型去最大化这个事件的期望次数，并在拍卖里用这个事件的价值来出价。
这里最容易犯的错误是目标与真实业务目标错位，例如：

\begin{itemize}
  \item 用「流量」目标买点击，结果拿到大量低质点击（信息流里的误触与好奇点击），
        加购率极低，看着 $\CPC$ 便宜，实际 $\CAC$ 更高。
  \item 用「落地页浏览」当作电商目标，等价于优化了一个与收入弱相关的事件，
        算法会优先找「爱点不爱买」的人。
  \item 目标层级过深（直接优化「购买」）而转化稀疏（一天不到 20 次），
        系统学不动，于是把量级压到很低，表现为「跑不出去量」。
\end{itemize}

实操上的常规解法是\kw{事件阶梯}：把优化事件从浅到深排成一条阶梯
（落地页浏览 $\to$ 内容浏览 $\to$ 加购 / 发起结账 $\to$ 购买 $\to$ 复购），
先用浅事件拿到足够的样本把模型预热，再逐步切换到深事件；当深事件样本不足而必须直接优化购买时，
就用成本上限或价值优化来约束系统。\cref{eq:learning} 会给出「样本够不够」的判据。

\subsection{Advantage+ 系列：把结构决策交给系统}

近几年的产品演进方向非常明确：\emph{把人工可调的结构变量逐层收回，交给系统做全局优化}。
这条路线在 Meta 上体现为 Advantage+ 家族，可以分成三类理解（\cite{meta_advantage}）：

\begin{enumerate}
  \item \textbf{Advantage+ 购物广告（Advantage+ Shopping Campaign）}：把「找受众 + 分配预算 + 选素材」
        合并成一个自动化容器，只保留国家、预算、素材与少量排除项作为人工输入。
        它的隐含假设是：\emph{系统掌握的跨用户行为信号比你的标签体系更全}。这个假设在多品类的成熟账户上
        通常成立，但在冷启动、极窄品类（专业配件）、强合规限制（医疗、金融）场景下会失效。
  \item \textbf{Advantage+ 受众（Advantage+ Audience）}：你给出一个「建议」受众（作为信号而非硬约束），
        系统可以在建议之外扩量。它把「受众」从\emph{过滤条件}降级为\emph{先验提示}。
  \item \textbf{自动素材（Advantage+ Creative / 素材增强）}：自动做画面裁剪、亮度和对比度调整、
        音乐替换、文案变体、商品标签叠加等。它的收益来自「用系统生成更多变体参与探索」，
        风险是可能破坏品牌调性与合规表述，所以必须逐项开关审核，尤其是涉及功效宣称的行业。
\end{enumerate}

\begin{insight}[自动化的收益与代价必须分开算]
把结构交给系统会带来一个隐蔽的代价：\textbf{可解释性下降}。当一条广告跑了三天突然掉量，
在手动结构下你可以逐层排查「是受众饱和了、还是出价被压了、还是素材衰变了」；
在完全自动化下，这三者被耦合在一起，你只能看到结果。
因此成熟团队的做法通常是\emph{混合结构}：用一条自动系列吃「大盘走量」，
同时保留若干条结构清晰的手动系列，专门用来做假设检验与归因诊断。
自动系列负责赚钱，手动系列负责让团队保持理解能力。
\end{insight}

\subsection{版位与自动版位的影响}

版位（Placement）决定广告出现在哪里：Facebook 动态、Instagram 动态、Reels、Stories、探索页、
Audience Network（站外应用与网站）、Messenger 等。默认的\kw{自动版位}让系统在所有可用位置分配预算，
这在绝大多数情况下能降低 $\CPM$ 并扩大触达，但它同时引入了两个必须监控的问题：

\begin{itemize}
  \item \textbf{版位间的转化率差异巨大}。Reels 与 Stories 是竖版沉浸式消费，用户注意力短、误触率高、
        转化路径长；动态与探索页的点击更「有意图」。同一个素材在两个版位上的 $\CVR$ 可能相差 2--5 倍。
  \item \textbf{素材规格不匹配造成的隐性损耗}。把 1:1 素材硬塞进 9:16 的 Reels 版位，会留黑边或裁掉主体，
        用户 1 秒内划走，系统学到「这条素材在 Reels 上很差」，从而压缩整体探索。
\end{itemize}

正确的做法不是关掉自动版位，而是\kw{按版位准备素材并单独体检}：至少在 9:16 与 1:1 两个比例上
各有一条完整可用的素材；在报表里按版位拆分 $\CTR$、$\CVR$、$\CPM$ 与 $\CPA$，发现某个版位
持续 2 周以上「高消耗 + 低转化」再考虑排除。\cref{tab:placement} 给出一份按版位看指标的口径表。

\section{定向：从精细收窄到广泛放量的钟摆}
\label{sec:meta-targeting}

\subsection{三类受众}

Meta 的受众体系可以按「数据来源」分成三层，这个划分比界面上的枚举更有解释力：

\begin{enumerate}
  \item \textbf{核心受众（Core Audience）}：由平台自身的人口属性（年龄、性别、地区、语言）、
        兴趣（Interest）与行为（Behavior）组成，是\emph{平台推理出来的标签}。
        它的优势是覆盖面广、无需自有数据；劣势是标签的精度随平台隐私政策收紧而系统性下降，
        且高人气的兴趣标签（如「时尚」）里混杂了大量无关人群。
  \item \textbf{自定义受众（Custom Audience）}：由\emph{你自己的数据}构造，包括
        网站像素与 CAPI 事件（访客、加购未购、已购）、App 事件、客户名单上传（邮箱 / 手机号哈希匹配）、
        以及互动数据（视频观看 95\%、主页互动、表单提交、广告点击）。这是精度最高的一层，
        也是唯一能把「老客复购」与「新客获取」分开的一层。
  \item \textbf{类似受众（Lookalike Audience）}：以某个自定义受众为种子，让平台在目标国家里找出
        特征相似的人群。可选 1\%--10\% 的规模档位。经验规律是：
        \emph{种子质量决定上限，档位决定成本}——1\% 最像但规模小、$\CPM$ 高；
        5\%--10\% 规模大、$\CPM$ 低但精度下降、开始出现明显泛量。用 1\% 做精准收割、
        用 3\%--5\% 做规模化往往是更稳的组合。
\end{enumerate}

\subsection{广泛定向（Broad）为什么回归}

2018 年前后的主流打法是「兴趣叠加 + 类似受众 1\%」，靠人工标签收敛人群；
之后的演进方向几乎完全相反：把受众设置成\emph{尽可能宽}（只保留国家、年龄下限与性别），
让系统在素材与出价给定的条件下自己找人。回归的原因有三条，缺一不可：

\begin{enumerate}
  \item \textbf{模型能力的提升}。排序模型从「标签匹配」进化到「用行为序列做表征学习」
        （参见 \cref{ch:sequence} 里序列建模的同类思路），能在冷启动用户上也做出可用的预估。
  \item \textbf{隐私政策造成的标签失效}。iOS ATT 之后，跨应用追踪需要用户显式授权，
        第三方数据回传减少，\emph{兴趣标签本身的精度与覆盖都下降了}（以官方最新文档为准）。
        当标签变脏，人工收窄就从「减少浪费」变成「减少探索」。
  \item \textbf{探索预算的机制价值}。收窄的受众意味着模型可探索的空间小，
        容易在局部最优里震荡；宽受众给了模型更大的探索空间，
        让它用「谁能转化」而不是「谁被打过标签」来做决策。
\end{enumerate}

\begin{pitfall}[扩量时同时改受众、出价与素材]
\textbf{现象}：某账户要把日耗从 300 美元提到 1200 美元，团队一次性做了三件事——
把类似受众从 1\% 放宽到 5\%、把出价从成本上限改成最低成本、
同时上了 6 条新素材。结果三天后 $\ROAS$ 从 2.4 掉到 1.1，消耗涨了但与收入不匹配。
团队复盘时无法判断是哪一个改动造成的，只能全部回滚，浪费了两周。\\
\textbf{根因}：三个变量同时变动，观测到的结果是一个\emph{耦合效应}，
在统计学上等价于把三个处理同时施加且没有对照，任何归因都是猜测；
更严重的是学习期被重置，历史样本被丢弃（见 \cref{eq:learning}）。\\
\textbf{排查与制度约束}：
(1) 扩量必须\emph{单变量推进}，每次只动一个维度，并留出至少 3--7 天的观察窗口；
(2) 受众、出价、素材三类改动的优先级是「素材 > 受众 > 出价」，
        因为素材的迭代成本最低、可回滚性最好；
(3) 每次改动前记录「改动日志」（时间、变量、旧值、新值、预期方向），
        报表按改动分段时间对比，这也是 \cref{sec:meta-attribution} 增量测试的基础数据；
(4) 若确实需要同时改，就新开一条系列承载新组合，与老系列并行跑，让预算分配去做自然选择。
\end{pitfall}

\section{信号与追踪：ATT 之后的投放地基}
\label{sec:meta-signal}

\subsection{Pixel、CAPI 与事件去重}

\term{Meta Pixel}{Meta 像素}是浏览器端的事件采集脚本，它在用户浏览器里捕获页面浏览与标准事件，
并把事件随请求发给 Meta。它的结构性缺陷是：依赖浏览器、
受广告拦截与浏览器隐私策略影响、且\emph{在 iOS 上大量事件因未授权而丢失}。

\term{Conversions API}{转化 API，CAPI}把同一批事件从\emph{服务器}直接发出，
不经过浏览器，因此不受拦截脚本与部分浏览器限制影响，并能携带更丰富的参数
（订单价值、商品 ID、哈希后的用户标识等）。行业经验上，双侧部署（Pixel + CAPI）相比仅 Pixel，
可见事件数通常有明显提升（常见报告在 10\%--30\% 量级，具体因品类与流量结构差异很大，属示范量级）。

双侧部署立刻带来一个新问题：\kw{同一个转化被上报两次}。解决方案是\emph{事件去重}
（deduplication），机制是给同一业务事件在两侧分配同一个 \code{event\_id} 与事件名：
浏览器端与服务端各发一次，事件名相同、\code{event\_id} 相同，
平台在服务端按这两者做合并，只计一次。工程上有几条硬要求：

\begin{itemize}
  \item \code{event\_id} 必须\emph{稳定且唯一}：建议用订单号或「会话 ID + 事件类型 + 时间戳」生成，
        同一业务事件在页面刷新、重试、用户返回时重复触发也必须得到同一个 ID。
  \item 事件名与参数必须\emph{大小写与结构一致}，否则会被当作两个不同事件，去重失效。
  \item 时间戳要同时带客户端与服务端，偏差过大会影响归因窗口的判定。
  \item 去重是\emph{平台侧行为}，你无法在本地验证结果，只能用「事件数 / 订单数」的比值
        做长期监控（该比值显著大于 1 时说明去重可能失效）。
\end{itemize}

\subsection{AEM 与 iOS ATT 后的信号损失}

iOS 的 App Tracking Transparency（ATT）要求应用在跨应用追踪前获得用户显式授权，
未授权用户的跨应用标识不可用。这带来的直接后果是受众网络与转化回传的可见性下降。
Meta 的应对机制之一是 \term{Aggregated Event Measurement}{聚合事件度量，AEM}：
它对每个域名允许配置有限数量的\emph{优先级事件}（行业常见说法是最多 8 个，
\textbf{具体数量与规则以官方最新文档为准}），
按优先级把未授权用户的事件做聚合上报，并对报告做延迟与聚合处理以保护隐私。
这带来三条实操后果：

\begin{enumerate}
  \item \textbf{优先级排序是业务决策}。排在后面的浅层事件（如内容浏览）可能失去可见性，
        如果你的优化事件恰好在优先级之外，报表会明显偏低。
  \item \textbf{报告有延迟与回填}。当天的转化数据通常不是终值，用当天数据做「素材生死判决」非常危险。
  \item \textbf{跨域与子域需要验证}。品牌站与独立结算域必须在同一套域名验证下正确配置，
        否则事件会落在不同域名上，优先级配置失效。
\end{enumerate}

在信号不全的条件下，平台会用\kw{建模转化}（modeled conversions）与统计推断来补齐：
对无法观测到的转化，用可观测的特征分布做概率估计，并在报表里标注为估算。
这解释了一个常见的困惑：后台报的转化数有时\emph{大于}你能逐单核对的订单数。
这不是 bug，而是建模值与观测值的混合。正确态度是：\emph{把平台报表当作优化信号，把自有后台当作结算真相}，
两者永远不要混用在同一张 KPI 表里（详见 \cref{sec:meta-attribution}）。

\subsection{归因窗口：1 日点击与 7 日点击的口径差异}

归因窗口决定了「一次点击之后多久内发生的转化算作这次点击的功劳」。常见口径包括
1 日点击、7 日点击、1 日浏览等，\textbf{可选值与默认值随产品更新变化，以官方最新文档为准}。
口径差异对同一批数据的影响非常大：同一个账户，把口径从 1 日点击切到 7 日点击，
报表转化数增加 20\%--60\% 属于常见区间（示范量级，强依赖品类决策周期）。

关键结论有三条：
\begin{itemize}
  \item \textbf{窗口越长，数字越好看，但越容易把自然转化算成广告功劳}。
        尤其是复购型业务，长窗口会把「本来就会买」的老客计入新客转化。
  \item \textbf{口径必须与决策场景匹配}。日常优化用与优化事件一致的短窗口（更快反馈）；
        预算与渠道评估用长窗口或增量口径（更接近真实贡献）。
  \item \textbf{任何跨渠道对比都必须在同口径下做}。用 Meta 的 7 日点击去比 Google 的
        数据驱动归因，等于用两把不同的尺子量同一根木头。
\end{itemize}

\subsection{服务端打标：GTM SS 与第三方托管}

服务端打标（server-side tagging）把原本在浏览器里跑的打标容器搬到一台\emph{你控制的服务器}上，
浏览器只向你自己的子域发送数据，再由服务端做转换、充实与转发。常见实现是
Google Tag Manager 的服务端容器（GTM SS），用于 Meta CAPI，也常用于 TikTok Events API；
托管型方案（如 Stape 这类第三方服务）把服务器运维外包，代价是数据经过第三方。

\begin{toolbox}[服务端打标（GTM SS / 托管方案）部署要点清单]
\begin{enumerate}
  \item \textbf{子域隔离}：用 \code{track.example.com} 之类的独立子域承载打标端点，
        与站点主域解耦，便于限流、升级与故障隔离；证书与 CORS 单独配置。
  \item \textbf{事件契约先行}：先把事件字典（事件名、触发时机、必填参数、\code{event\_id} 生成规则、
        币种与金额口径）写成文档并对齐前后端，再动容器配置；否则会出现「同一事件两种参数结构」。
  \item \textbf{去重验证}：在测试环境人为制造重复上报（刷新、返回、重试），确认平台侧事件数不翻倍；
        上线后用「事件数 / 订单数」比值做周度监控与告警。
  \item \textbf{PII 处理与哈希}：邮箱、手机号一类标识必须按平台要求做规范化（去空格、统一小写）
        再哈希，禁止明文传输；哈希算法与规范化规则要写进事件契约。
  \item \textbf{合规与同意管理}：把同意状态（Consent）作为事件参数传入，
        未授权用户不发送可识别标识；对照 GDPR / CCPA 与平台政策，跨境业务还要考虑数据出境要求。
  \item \textbf{可用性监控}：为打标端点设置可用率、P95 延迟、5xx 比例告警；
        容器故障时要有「降级到浏览器端」的预案，避免信号完全中断。
  \item \textbf{灰度与回滚}：先在 5\% 流量上验证事件数与参数完整度，再全量；
        保留旧通路的开关，确保 10 分钟内可回滚。
\end{enumerate}
\end{toolbox}

\begin{casebox}[案例：某 DTC 品牌双侧部署后的三个月（示范案例）]
一个客单价约 60 美元、复购周期约 90 天的家居 DTC 品牌，在 iOS 政策收紧后出现两个症状：
后台报告的加购事件骤降，同时 $\CPA$ 看起来「变差了」，团队准备砍掉表现最差的三个广告组。
在动手前，他们先做了三件事（数据为示范量级，仅用于说明方向）：
(1) 上线服务端打标，用统一的 \code{event\_id} 做去重，双侧部署后可见的购买事件数从
        约 600 单/周提升到约 780 单/周，加购事件提升更明显；
(2) 把报表默认口径从 1 日点击切换为 7 日点击，同时\emph{另存}一份 1 日点击视图专门用于日常优化，
        避免口径混用；并把当天数据的「回填校正」纳入日报流程（当天数字只做趋势参考）；
(3) 用自有订单库做了一次对账，发现平台报的购买数比实际订单多约 35\%，
        其中大部分是长窗口归因与建模转化的贡献。

\textbf{结果与结论}：原本被判为「最差」的两个广告组在信号补齐后表现回到中游；
被误砍的真正原因是\emph{信号缺口让系统无法看到它们的转化}，而不是受众或素材不行。
这个案例的可迁移结论是：\textbf{在信号缺失的环境里做素材与受众的取舍，很容易把「看不见」误判成「不work」}；
先修地基，再做剪辑。另需注意，本例中的数值只反映该品类与流量结构下的量级，
不同业务的提升幅度会显著不同。
\end{casebox}

\subsection{素材矩阵：钩子、卖点、形式、人群}

素材之所以被称为「定向」，是因为它同时在四个维度上筛人。
把这四个维度写成一张笛卡尔积表，团队就有了可执行的产能规划：

\begin{enumerate}
  \item \textbf{钩子（Hook）}：前 1--3 秒抓住注意力的机制。常见类型有
        痛点直击（「还在为 XX 头疼」）、反差/悬念（前 3 秒说一个违反常识的结论）、
        结果前置（先展示使用后的效果再回溯）、身份标签（「30 岁通勤族」）、
        价格锚点（「比 XX 便宜一半」）、视觉冲击（极端近景、ASMR、强对比拆解）。
  \item \textbf{卖点（Value Proposition）}：功能、价格、材质、场景适配、情绪价值、社交证明。
        一条素材只讲\emph{一个}主卖点，讲两个等于两个都没讲透。
  \item \textbf{形式（Format）}：口播测评、开箱、剧情、纯展示（静物快剪）、图文轮播、
        对比实验、达人推荐、直播切片。
  \item \textbf{人群（Audience）}：新手 / 进阶 / 送礼 / 自用 / 家庭 / 专业用户等。
        注意人群在这里是\emph{素材语义}而非后台的受众设置——这正是「素材即定向」的字面含义。
\end{enumerate}

\subsection{3 秒留存率与完播率}

在信息流里，素材的漏斗是\emph{观看漏斗}而不是点击漏斗。三个层次需要分开度量：

\begin{itemize}
  \item \textbf{3 秒留存率}（3-second view rate）：起播后 3 秒仍在观看的比例，衡量钩子强度。
        这是最灵敏的指标，通常也是唯一能在几百次展示量级上就读出差异的指标。
  \item \textbf{完播率}（completion rate）与 15 秒 / 25\% / 50\% / 75\% 分段留存：
        衡量中段叙事与节奏。短素材（$<15$ 秒）完播率天然更高，不要跨时长直接比较。
  \item \textbf{互动与转化}：点赞、评论、分享、收藏、加购、下单。前四个属于\emph{分发燃料}，
        后两个才是收入；只有互动没有转化，说明素材成功「骗到了注意力」但没有说服力。
\end{itemize}

\begin{equation}
R_{\text{hold3}} = \frac{V_{3}}{V_{\text{start}}}, \qquad
R_{\text{comp}} = \frac{V_{\text{end}}}{V_{\text{start}}}, \qquad
R_{\text{hold3}} \times R_{\text{comp}} \approx \text{有效注意力占比}.
\label{eq:hold}
\end{equation}

\begin{formulacard}[素材疲劳的三信号判据]
疲劳不是一个感觉，而是一组在时间序列上同向变化的信号。设某素材在时间窗 $t$ 上的
展示频次为 $F_t$、点击率与转化率为 $\CTR_t$、$\CVR_t$，单次转化成本为 $\CPA_t$：
\begin{equation}
\text{疲劳判据:}\quad
\frac{F_t}{F_{t-1}} > 1 + \eta, \quad
\frac{\CTR_t}{\CTR_{t-1}} < 1 - \delta, \quad
\frac{\CPA_t}{\CPA_{t-1}} > 1 + \lambda ,
\label{eq:fatigue}
\end{equation}
即\textbf{频次上升、点击率下降、转化成本上升三者同时出现}，才可判定为疲劳。
经验阈值（示范量级）：$\eta \approx 0.15$--$0.25$、$\delta \approx 0.15$--$0.25$、
$\lambda \approx 0.15$--0.30，且要求相邻窗口各自至少有 10--20 次转化、
\textbf{观察窗口不少于 3 天}，否则波动会淹没信号。
\textbf{只满足其中一条时不要淘汰素材}：$\CTR$ 下降但频次未升，往往只是人群重叠；
$\CPA$ 上升但 $\CTR$ 稳定，优先怀疑落地页或库存价格变动（见 \cref{ch:cro}）。
\end{formulacard}

\begin{insight}[素材不是消耗品，而是可累积的资产]
多数团队只把素材当消耗品：跑完就丢，下次从零开始。

这也是为什么素材编号与投放编号必须一一对应：没有映射，就没有沉淀。
\end{insight}

\subsection{素材测试方法论：同预算 A/B 与最小样本}

素材测试最容易犯的错误是「比$\CTR$ 选素材」：在同预算下，$\CTR$ 高的素材常常消耗更快、
曝光人群更浅，反而在$\ROAS$ 上落后。正确的判据应当围绕\emph{单位预算的产出}与\emph{单位转化的成本}。
在给定显著性水平 $\alpha$ 与检验功效 $1-\beta$ 下，比较两个素材的转化率 $p_1, p_2$ 所需的
每组最小样本量（每组的\emph{展示或点击}数）为：

\begin{equation}
n_{\min} \;\approx\; \frac{\left(z_{1-\alpha/2}\sqrt{2\bar p(1-\bar p)}
+ z_{1-\beta}\sqrt{p_1(1-p_1)+p_2(1-p_2)}\right)^2}{(p_1-p_2)^2},
\qquad \bar p = \frac{p_1+p_2}{2}.
\label{eq:samplesize}
\end{equation}

\begin{equation}
n_{\min}^{\text{order}} \;\approx\; \frac{16\,\bar p\,(1-\bar p)}{(\Delta p)^2},
\qquad \Delta p = \abs{p_1-p_2} ,
\label{eq:samplesize-approx}
\end{equation}

\cref{eq:samplesize-approx} 是常用的快速近似：当 $\alpha=0.05$、功效 $0.8$ 时系数约为 16。
它的实务含义相当残酷——若基线转化率 $\bar p = 2\%$，
要检出\emph{相对} 20\% 的提升（即 $\Delta p = 0.4$ 个百分点），每组需要的样本量在
$10^4$ 量级（以点击或会话为单位）。这意味着：
\begin{itemize}
  \item 用一天几百次点击的流量去做素材 A/B，\emph{在统计上不可能得出结论}，
        看到的「A 比 B 好 30\%」几乎全是噪声。
  \item 在低流量账户上，正确的做法不是「做更精细的 A/B」，
        而是\emph{放宽判断标准}：只看是否会「明显崩」（例如 $\CPA$ 超过目标 2 倍），
        其余素材全部并行保留，让预算分配机制去做长期选择。
  \item 对于视频素材，可以在\emph{上游指标}上做高灵敏度检验：
        3 秒留存率与 $\CTR$ 的样本方差远小于 $\CVR$，
        因此「钩子级」的判断可以用小样本，而「卖点级」的判断必须用大样本。
        这是素材测试里最重要的分层原则（见 \cref{tab:testlevel}）。
\end{itemize}

\begin{toolbox}[素材测试预算的分配与节奏]
\begin{enumerate}
  \item \textbf{总预算三分法（经验配比，示范量级）}：把日预算切成
        60\% 给已验证的「现金牛」素材、25\% 给在测素材、15\% 给探索性素材（新钩子 / 新形式）。
        测试预算被封顶，是防止「为了做实验把账户做亏」的制度设计。
  \item \textbf{同预算平行投放}：把待测素材放在\emph{同一条}广告组的多个广告（Ad）层级下，
        或放在预算完全相同的多条广告组下，让平台在同一人群池里分配曝光；
        不要给候选素材配不同的受众或出价。
  \item \textbf{单条素材的测试门槛}：给每条候选素材一个「最低消耗门槛」
        （例如至少 2--3 倍目标 $\CPA$ 的消耗），未过门槛不做判断；
        过了门槛仍无转化，才归档。
  \item \textbf{批量而非单条}：一次上 6--12 条候选，按 3 秒留存率先砍一半，
        剩下的用转化指标做二次筛选。单片对比的效率远低于批量筛选。
  \item \textbf{记录并复用结论}：每条素材归档时填写「钩子类型 / 卖点 / 形式 / 人群 / 死因」，
        月度汇总成钩子胜率表，直接指导下个月的选题方向。
  \item \textbf{口径固定}：测试期全部使用同一归因窗口与同一优化事件，
        否则跨素材比较毫无意义（见 \cref{sec:meta-signal}）。
\end{enumerate}
\end{toolbox}

\subsection{UGC 与达人素材}

\term{UGC}{User Generated Content，用户生成内容}素材的核心优势不是「便宜」，而是\kw{可信度与原生度}：
它以普通用户的口吻与画质出现，绕过了用户对广告的心理防御。
它的代价是质量方差大、可控性差、且需要解决版权与授权（达人授权通常有\emph{使用期限}与\emph{投放范围}限制，
用于付费投放时必须取得明确的广告授权，具体条款以平台与合同约定为准）。

达人素材的常见组织结构是\kw{达人矩阵}：
头部达人负责「引爆」——他的价值在于带来话题、搜索量与自然流量溢出，
$\ROAS$ 往往不高但\emph{外溢效应}显著；腰尾部达人负责「铺量」——
单价低、产条数多、内容更垂直，是付费投放素材的主要来源。
衡量矩阵效率不能只看单条的 $\ROAS$，而要看「同款商品在自然流量与品牌词搜索量上的同期变化」，
这也是 \cref{sec:meta-attribution} 里增量思维的又一次应用。

\begin{casebox}[案例：一周 30 条素材的批量生产与测试结果分布（示范案例）]
一个美妆工具类目团队（客单价约 25 美元）把素材生产改成周更流水线，为期 8 周。
流程是：周一从评论区与客服工单里提取 20 条用户原话作为选题；
周二按「1 个钩子 $\times$ 1 个卖点」的粒度写出 20 个 15 秒脚本；
周三一次拍摄完成 8 个钩子的素材母版（同一卖点同一场景）；
周四剪辑出 30 条成品（同一母版做字幕、节奏、开场画面变体）；
周五上线测试。8 周的数据分布（示范量级，仅说明形状而非精确值）：

\begin{itemize}
  \item 约 50\%--60\% 的素材在消耗达到测试门槛后仍无转化，被直接归档；
  \item 约 25\%--30\% 的素材表现平平（$\ROAS$ 接近账户均值），保留作为结构填充；
  \item 约 10\% 的素材成为「现金牛」，单条贡献了当周 40\% 以上的收入；
  \item 8 周内共跑出 4 条「爆款」，它们的共同特征是：\textbf{前 3 秒出现具体使用场景 + 明确结果展示 +
        字幕在前 1 秒就给出核心卖点}；而失败的素材中，最多的死因是
        「前 3 秒是品牌 logo 或纯产品空镜」。
\end{itemize}

\textbf{可迁移的结论}：(1) 素材的胜率是\emph{产量}的函数，不是\emph{单条质量}的函数——
没有产量就没有筛选空间；(2) 同一母版做多剪辑是成本最低的变体来源，
因为它把「拍摄成本」摊薄到多条素材上；(3) 钩子台账让第二个月的选题从「猜」变成「排除已知失败模式」。
同时也必须承认，这个分布强依赖品类、客单价与流量结构，不能当作通用基准。
\end{casebox}

\subsection{Spark Ads 与自然流量复用}

\term{Spark Ads}{原生加热广告}允许把\emph{真实的自然帖}（自己账号或达人账号的帖子）
作为广告素材投放。它的价值来自三点：
(1) 帖子已经过自然流量验证，互动数据是真实的；
(2) 广告保留了原帖的点赞、评论与主页链接，用户点击后进入的是达人主页或品牌号，
社交证明完整；
(3) 自然流量与付费流量在同一帖子上叠加，平台的推荐模型能看到更强的互动信号，
带来额外的自然分发溢出。

它的工程要点是\kw{授权与生命周期管理}：授权码有有效期，授权过期后广告会停止或无法继续投放；
帖子的评论需要有人维护（负面评论会直接出现在广告位下方，
而广告位下的评论是公开可见的）；同时要区分「自然表现好」与「广告表现好」，
自然播放量高的帖子不一定是好的转化素材（可能与商品无关）。

\subsection{内容原生度要求}

TikTok 的用户对「广告感」极其敏感，这带来一组硬性内容要求（属于行业共识与平台创意建议，
具体规范以官方最新文档为准）：

\begin{itemize}
  \item \textbf{竖屏、满屏、前置主体}：9:16，主体在第一秒就出现在画面中央，避免开场留白与横屏转竖屏。
  \item \textbf{前 3 秒必须有信息}：说出一句结论、展示一个结果、或抛出一个强反常识的问题；
        不要用 logo 开场，不要用长片头。
  \item \textbf{像用户而不是像品牌}：手持感、现场音、口语化字幕、真实环境光。
        过度精修的广告片在 TikTok 上通常比 UGC 表现更差。
  \item \textbf{字幕与静音可看}：大量用户静音刷，字幕要在前 1 秒给出核心信息，字号够大、位置避开下方 UI。
  \item \textbf{明确且自然的行动指引}：用小黄车、评论区置顶、主页链接等方式承接，
        避免生硬的口播促销语堆砌。
\end{itemize}

\begin{insight}[TikTok 的「内容--交易闭环」改变了素材的功能]
在传统电商漏斗里，素材的任务是「产生点击」，成交发生在站外。
而在 TikTok Shop 的闭环里，素材可以直接挂商品、在视频内完成加购与结算
\cite{tiktokshop_about}。这带来一个结构性变化：
\textbf{素材的 KPI 从「点击率」变成了「转化率 + 客单价」}，
因为用户不需要离开信息流。相应地，素材必须把「商品信息」而非「品牌故事」放在最前：
价格、规格、使用场景、售后承诺要在视频内讲完。
换言之，闭环缩短了链路，但也把原本由落地页承担的说明责任\emph{压回了素材内部}。
这正是 \cref{ch:cro} 要接着讨论的问题——当链路被压缩，说服成本会转移，而不会消失。
\end{insight}

\subsection{达人矩阵：头部引爆与腰尾部铺量}

达人矩阵的设计目标不是「找最红的人」，而是\emph{用不同的层级解决不同的问题}：

\begin{itemize}
  \item \textbf{头部达人（引爆层）}：单条成本高，但能带来话题、品牌搜索量与自然流量外溢。
        考核指标应当包含\emph{品牌词搜索量、商品页自然流量、话题播放量}，
        而不能只用直接 $\ROAS$ 判死，否则会系统性地砍掉所有曝光型投入。
  \item \textbf{腰部达人（转化层）}：粉丝量与垂直度更匹配，单价可控，是「内容质量 + 转化」的平衡点。
        通常作为批量素材来源与测试场。
  \item \textbf{尾部达人 / 素人（铺量层）}：单价低、条数多，用于占满搜索结果与话题页，
        创造「到处都能看到」的密度感。这一层的价值在于\emph{内容密度}而不是单条效果。
\end{itemize}

矩阵的绩效评估需要把三层的指标与考核周期错开：引爆层看季度级的声量与搜索增量，
转化层看周级的 $\ROAS$ 与素材产出，铺量层看内容条数与覆盖密度。
用同一把尺子量三层，是达人投放最常见的资源错配来源。

\subsection{直播承接：GMV 的乘性分解}

直播是 TikTok 上承接大促流量的主要容器。它的收入可以精确地分解成一串乘性因子，
这个分解的价值在于：\emph{任何一环接近零，整体就接近零}，因此诊断必须找最短的那块板。

\begin{equation}
\GMV = I \times r_{\text{enter}} \times T_{\text{stay}} \times \CVR_{\text{live}} \times \AOV ,
\label{eq:livestream}
\end{equation}

其中 $I$ 是曝光量（feed impressions，包括自然推荐与付费投放），
$r_{\text{enter}}$ 是曝光到进入直播间的比例（封面与标题决定），
$T_{\text{stay}}$ 是平均停留时长（由话术节奏、货品结构与主播状态决定），
$\CVR_{\text{live}}$ 是进入后的下单转化率（由价格、库存、优惠机制与讲解效率决定），
$\AOV$ 是客单价（由组合装与连带推荐决定）。

对\cref{eq:livestream} 取对数得到可加形式，$ \ln \GMV = \ln I + \ln r_{\text{enter}} + \ln T_{\text{stay}} + \ln \CVR_{\text{live}} + \ln \AOV $，
这使得各因子的\emph{弹性}可以直接比较：曝光翻倍带来 $\ln 2 \approx 0.69$ 的增量；
而把平均停留从 40 秒提到 60 秒（$+50\%$）带来约 0.41 的增量，并且不额外花钱。
这解释了为什么直播间的第一优先级永远是\emph{承接能力}（停留与转化），而不是买更多流量：
在承接能力不变的前提下买流量，只会把预算倒进一个漏水的桶。

\begin{equation}
\frac{\partial \ln \GMV}{\partial \ln X} = 1 \quad \text{for every factor } X \in \{I, r_{\text{enter}}, T_{\text{stay}}, \CVR_{\text{live}}, \AOV\},
\label{eq:liveelasticity}
\end{equation}

即每个因子的弹性都是 1（等比例改善带来等比例收入增长），
所以决策规则是：\textbf{优先改善边际成本最低的那个因子}。
对多数直播间来说，这个因子是停留时长与讲解效率，而不是曝光量。

\term{DSP}{Demand Side Platform，需求方平台}一侧要区分两类用法：
一类是\emph{重定向与频次控制}（把站内行为数据接入 DSP，对加购未购人群做跨站承接），
另一类是\emph{开放网络的规模化曝光}（The Trade Desk、Criteo、RTB House 这类平台各自有侧重，
具体库存与产品能力以官方最新文档为准）。DSP 的常见陷阱是「看起来什么都能投」——
由于库存来源分散、归因链路长，如果没有独立的衡量体系（增量实验、
品牌提升调研或明确的频次--转化曲线），很容易出现「报表漂亮但增量存疑」的局面。

\section{冷启动与放量方法论}
\label{sec:meta-scaling}

\subsection{学习期与「50 次转化」门槛}

主流平台的自动出价机制都需要一段\emph{学习期}：系统用有限的时间窗（常见为 7 天，
以官方最新文档为准）收集事件样本，训练该广告组的预估模型。
行业通行的经验门槛是\kw{单周 50 次转化}（示范量级，不同平台与优化事件会有差异）：
低于这个量级，模型的预估方差过大，表现为消耗不稳、$\CPM$ 抖动、$\CPA$ 时好时坏。

\begin{equation}
N_{\text{week}} \;\ge\; N_{\text{learn}} \approx 50 ,
\qquad
B_{\min} \;\approx\; \frac{N_{\text{learn}} \cdot \CPA_{\text{target}}}{7} \times s ,
\qquad
s \approx 1.2\text{--}1.5 .
\label{eq:learning}
\end{equation}

\cref{eq:learning} 中 $s$ 是安全系数（用于吸收投放初期的波动与竞争抬价）。
它有一个非常实用的推论：\emph{预算下限由目标转化成本和门槛共同决定}。
若目标 $\CPA$ 是 30 美元，那么为了让一个广告组在一周内拿到 50 次转化，
日预算至少要 $50 \times 30 / 7 \approx 214$ 美元（再乘安全系数）。
如果你的账户一天只有 300 美元总预算，那么\kw{你根本没有能力养两个广告组}——
强行拆成五个广告组，每个都在学习期里饿死。这也直接推导出冷启动的结构原则：
\emph{预算越小，结构必须越简单}。

\begin{pitfall}[用平台报的「转化数」判断真实增量]
\textbf{现象}：某团队发现开通 Meta 的进阶赋能系列后，后台 $\ROAS$ 从 2.1 升到 3.4，
于是把 Google 品牌词预算砍了 40\% 挪给 Meta。一个月后总收入没涨、总利润下降。\\
\textbf{根因}：三件事叠加。
(1) \textbf{归因窗口重复计数}：Meta 的长点击窗口把同一批订单也记了一次，
        而 Google 的品牌词订单同样会记一次，两个平台的「功劳」有大量重叠（\cref{eq:doublecount}）；
(2) \textbf{建模转化的补偿}：信号缺失时平台用模型补齐数字，补齐的部分不等于增量；
(3) \textbf{品牌词被抢}：用户先看到品牌词搜索广告再点 Meta 广告，Meta 会把这笔订单记成自己的功劳，
        而实际上需求来自搜索。\\
\textbf{排查与修正}：
(1) 所有渠道评估必须使用\emph{同一口径}，并优先看\emph{增量}而非\emph{归因}（\cref{eq:incrementality}）；
(2) 建立「平台归因之和 / 自有订单数」的月度比值监控，比值持续大于 1.2 就说明重复计数严重；
(3) 做一次\emph{品牌词暂停测试}（见 \cref{tab:incrementaltest}）验证品牌流量的真实贡献，
        再决定预算迁移；
(4) 迁移预算时按 20\%--30\% 的步长分批，并保留对照组，不要一次砍 40\%。
\end{pitfall}

\subsection{测试期、放量期、稳定期}

三个阶段的目标完全不同，用同一套 KPI 考核三个阶段是常见的组织性错误：

\begin{enumerate}
  \item \textbf{测试期（多素材、小预算）}：目标是\emph{找出可用的素材与受众组合}。
        做法是用小预算（每条素材仅够拿到钩子级样本）并行投放 6--12 条素材，
        用 3 秒留存率与 $\CTR$ 做初筛，用 $\CVR$ 做复筛（\cref{tab:testlevel}）。
        考核指标是\emph{命中率}（跑出可放量素材的比例）与\emph{单条发现成本}，而不是 $\ROAS$。
  \item \textbf{放量期（CBO / ABO、预算加倍节奏、扩量受众）}：目标是\emph{在可控成本下扩大规模}。
        关键工具是预算模式的选择（CBO 让系统在广告组间分配，ABO 保持单组可控）与
        \emph{加预算节奏}。
  \item \textbf{稳定期（素材迭代节奏、再营销与老客复购分离）}：目标是\emph{维持边际效率}。
        素材按固定节奏迭代（例如每周补 5--10 条候选），
        并把再营销（老客 / 加购未购）与新客获取\emph{分账户或分系列}考核，
        否则老客的低成本转化会掩盖新客获取的真实难度。
\end{enumerate}

\subsection{预算加倍曲线}

加预算不是线性的。$\CPA$ 随消耗增长而上升，原因是每一层预算都要买到更外围的人群。
一个常用的经验模型是指数形式：

\begin{equation}
\frac{\CPA(B)}{\CPA(B_0)} \;=\; \left(\frac{B}{B_0}\right)^{\gamma},
\qquad \gamma > 0 ,
\label{eq:budgetscale}
\end{equation}

其中 $B_0$ 是「当前效率稳定点」的日预算，$\gamma$ 是\kw{规模弹性系数}。
经验上 $\gamma$ 常见落在 0.3--0.8 之间（示范量级）：
$\gamma$ 越小，说明账户越能「便宜地扩量」；
$\gamma$ 接近或大于 1 说明该结构已接近饱和，继续加预算会等比甚至更快地推高成本。
反向使用这个式子还可以估出\emph{成本可接受上限}对应的最大预算：
若你接受 $\CPA$ 上升 30\%（即比值 1.3）、$\gamma = 0.5$，
则 $B / B_0 = 1.3^{1/0.5} \approx 1.69$，也就是最多加到当前预算的约 1.7 倍。

\cref{eq:budgetscale} 直接给出了加预算的操作节奏：\textbf{每次加幅不超过 20\%--30\%，
间隔至少 24--72 小时}，让系统在新预算下重新稳定并观察效率变化；
单次加幅过大（例如翻倍）会重置学习、造成成本尖峰，
而频繁小幅改动（一天改三次）同样会让系统一直在追一个移动的目标。
另一种更加可控的做法是\kw{垂直扩量}：不改现有系列，
而是复制一条结构完全相同的新系列、给独立预算，
让两条系列并行跑——这样规模的扩大不以牺牲原系列的稳定性为代价，
也天然形成了一个可比的对照（见 \cref{sec:meta-attribution}）。

\section{归因与对账：为什么每个平台都说是自己的功劳}
\label{sec:meta-attribution}

\subsection{重复计数的机制模型}

把「平台归因之和大于实际订单」这件事写成模型，问题会立刻变得清晰。
设有 $k$ 个投放渠道，用户的一笔订单可能被多个渠道的归因窗口覆盖。
简化假设：每一笔订单被渠道 $i$ 记入的概率为 $q_i$（即该渠道的窗口覆盖了这笔订单的触点），
且各渠道的覆盖近似独立（这个假设在跨渠道重定向盛行的环境里偏乐观，
因此下面的式子给出的是重复计数的\emph{下界}）：

\begin{equation}
\E\!\left[\sum_{i=1}^{k} C_i\right] \;=\; \sum_{i=1}^{k} q_i \, N \;\ge\; N \cdot \left(1 - \prod_{i=1}^{k}(1-q_i)\right) \;=\; \E[C_{\text{actual}}] ,
\label{eq:doublecount}
\end{equation}

\cref{eq:doublecount} 的两端只有在 $k=1$ 或 $q_i$ 很小时才接近。
当 $q_1 = q_2 = 0.6$（两个渠道都覆盖了六成订单）时，
两边分别是 $1.2N$ 与 $0.84N$——也就是说，
\textbf{平台归因之和可能比「至少被一个渠道覆盖的订单数」高出约 43\%}。
这个数字不是任何平台的错，而是\emph{窗口重叠的数学必然}。
把它写成\kw{三方差值}（oversummation）指标：

\begin{equation}
O \;=\; \frac{\sum_{i=1}^{k} C_i}{\max\left(C_{\text{actual}}, \epsilon\right)} ,
\label{eq:oversum}
\end{equation}

$O$ 的健康范围强依赖业务形态：长决策周期、多触点的品类（家居、家电）$O$ 常年在 1.3--2.0，
而冲动型快消可能接近 1.05--1.2（示范量级）。
它的用途不是「找出哪个平台在撒谎」，而是\textbf{判断你的渠道之间有多少重叠需求}，
并决定是否必须做增量测试。

\subsection{增量测试：三种可用方法}

因果推断的基本框架见 \cref{ch:ad} 与 \cref{ch:growth}，这里只讲在广告场景下可落地的三种。

\begin{equation}
\text{增量提升（Lift）} \;=\; \frac{Y_{\text{treatment}} - Y_{\text{control}}}{Y_{\text{control}}},
\qquad
\iROAS \;=\; \frac{\Delta \text{Revenue}}{\Delta \text{Spend}} .
\label{eq:incrementality}
\end{equation}

\begin{equation}
\Delta\text{Revenue} \;=\; \left(\bar y_{\text{treat}} - \bar y_{\text{ctrl}}\right) \times N_{\text{matched}} ,
\qquad
\mathrm{SE}(\Delta) \;=\; \sqrt{\frac{s_{\text{treat}}^2}{n_{\text{treat}}} + \frac{s_{\text{ctrl}}^2}{n_{\text{ctrl}}}} .
\label{eq:liftsignificance}
\end{equation}

\cref{eq:liftsignificance} 提醒一件事：增量实验常常是\emph{功效不足}的。
如果一个地区每周只有 300 单，把两个规模相近的地区做对比，
要检出 10\% 的提升需要非常长的时间窗（可达数周至数月），
所以地理 holdout 更适合回答「这个渠道到底有没有用」这样的\emph{方向性}问题，
而不适合做精细的素材级判断。三种方法的取舍见 \cref{tab:incrementaltest}。

\begin{keypoint}[归因是分配功劳，增量是判断有无]
把这两件事分开，投放管理的绝大部分争议都会消失：
\begin{enumerate}
  \item \textbf{平台报表用于日常优化}：它是高频、细粒度、与出价系统一致的信号，适合回答
        「哪条素材更好」「哪个受众更便宜」。
  \item \textbf{增量实验用于预算分配}：它是低频、粗粒度、代价高的证据，适合回答
        「这个渠道该不该继续投」「预算该往哪挪」。
  \item \textbf{自有订单库是唯一结算真相}。任何与收入、利润、财务相关的数字必须来自自有后台，
        平台报表只作为解释变量。
  \item 用 \cref{eq:oversum} 的 $O$ 值做月度体检：$O$ 升高不代表渠道变差，
        但一定代表\emph{渠道间重叠在增加}，此时继续按归因数字分配预算的风险在上升。
\end{enumerate}
\end{keypoint}

\section{本章小结与下一步}

\begin{keypoint}[本章要点回顾]
\begin{enumerate}
  \item Meta 与 TikTok 是推荐式广告，\textbf{素材本身就是定向与召回特征}。
        这决定了本章的重心必须落在素材工程，而不是受众标签的堆叠。
  \item 三层账户结构（Campaign / Ad Set / Ad）的本质是「变量分层」：
        目标与预算策略在最上层、受众与出价在中间、素材在最下层。
        \emph{预算与学习发生在哪一层，实验就必须在哪一层做}；
        改动越靠上，学习重置的代价越大（\cref{eq:learning}）。
  \item Advantage+ 家族把受众、预算与素材的决策逐步交给系统，收益是全局优化与更低的操作成本，
        代价是\emph{可解释性下降}。成熟团队用「自动系列赚钱 + 手动系列做实验」的混合结构化解这个代价。
  \item 自动版位能压低 $\CPM$、扩大触达，但版位间 $\CVR$ 差异巨大。
        正确做法是按版位准备素材规格，并按版位拆分体检，而不是简单地关闭自动版位。
  \item 定向经历了从「兴趣叠加 + 类似 1\%」到「广泛定向」的钟摆回归，
        驱动力是模型能力提升、隐私政策导致标签失效、以及探索空间的价值。
        但收窄与放量各有适用阶段（\cref{tab:broadtradeoff}）：
        样本密度不足时放太宽，等于让模型在噪声里学习。
  \item 信号地基是「Pixel + CAPI 双侧部署 + \code{event\_id} 去重」，
        再叠加 AEM 的事件优先级与建模转化。ATT 之后的报表是\emph{观测值与估算值的混合}，
        因此「后台转化数」只能当优化信号，不能当结算依据。
        1 日点击与 7 日点击的口径差异可达 20\%--60\%，任何跨渠道比较都必须先统一口径。
  \item 素材矩阵是四个维度的笛卡尔积：钩子 $\times$ 卖点 $\times$ 形式 $\times$ 人群。
        3 秒留存率是最灵敏的上游指标，$\CTR$ 与 $\CVR$ 是中下游指标，
        三者对应不同的最小样本量（\cref{eq:samplesize}、\cref{tab:testlevel}）。
  \item 素材疲劳必须用三信号联合判据（\cref{eq:fatigue}）：频次上升、$\CTR$ 下降、$\CPA$ 上升同时出现，
        且持续不少于 3 天。单条信号触发时先排查落地页、价格与人群重叠，不要急着换素材。
  \item 素材的胜率是产量的函数。批量生产流水线（选题库 $\to$ 脚本模板 $\to$ 拍摄 SOP $\to$ 剪辑模板）
        的意义是把单条素材的边际成本降到最低，并为「钩子--卖点--结果」台账积累可复用的结论。
  \item TikTok 的核心约束是内容原生度：竖屏满屏、前 3 秒给信息、UGC 质感优于精修广告片。
        Spark Ads 的价值在于复用已被自然流量验证的帖子，但必须管理授权期限与评论区。
        达人矩阵要按层级错开 KPI：头部看声量与搜索溢出、腰部看 $\ROAS$、尾部看内容密度。
  \item 直播 $\GMV$ 是五个因子的乘积（\cref{eq:livestream}），每个因子的弹性都是 1，
        所以决策规则是\emph{优先改善边际成本最低的因子}——
        对多数直播间而言是停留时长与讲解效率，而不是买更多曝光。
  \item 冷启动的硬约束是「学习期 + 约 50 次转化」，
        它反推出每个广告组的最低日预算（\cref{eq:learning}）。
        预算越小，结构必须越简单。放量要遵守单变量推进与 20\%--30\% 的加幅节奏（\cref{eq:budgetscale}），
        或者用复制新系列的垂直扩量保持原系列稳定。
  \item 归因与增量必须分开管理：平台报表回答「谁更便宜」，增量实验回答「该不该继续投」。
        三方差值（\cref{eq:oversum}）是渠道重叠程度的体检指标，
        而地理 holdout、PSA、品牌词暂停分别适合渠道级、创意级与搜索级的因果问题，
        切换前后对比只能当方向性线索（\cref{tab:incrementaltest}）。
\end{enumerate}
\end{keypoint}

Meta 与 TikTok 解决的是「用户没有表达需求时，如何用内容把他拉进来」这一层的增长，
它的优势是规模上限高、可快速测试，代价是流量成本持续上涨、
且素材资产的生命周期短（以周计）。
而当用户\emph{真的}被拉进了落地页之后，转化率就成了唯一能自己控制的杠杆——
同样的流量，落地页好坏可以让收入相差数倍。
